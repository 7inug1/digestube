# 로컬 전용 — 음성만 Gemini 에 넘기기

2026-09-27 · 상태: **측정 전 고정안**

## 왜

지금은 배포·로컬 모두 유튜브 주소를 Gemini 에 넘긴다. Gemini 는 화면(1초 1프레임, 66토큰)과
소리(초당 32토큰)를 함께 입력으로 받는다. 결과로는 소리만 받아쓰는데(프롬프트가 화면 글자를 옮기지 않게 함),
화면 몫 입력 비용이 입력의 약 70% 다. 85분 영상 약 1,000원 중 입력 약 600원.

서버는 유튜브 다운로드가 막혀 있어 다른 길이 없다. **집 인터넷(로컬)은 음성을 내려받을 수 있다.**
음성만 넘기면 같은 모델로 입력이 약 1/3 이 된다. 유튜브 주소로는 프레임 수를 줄이는 설정도 안 된다
(https://ai.google.dev/gemini-api/docs/video-understanding, 2026-09-27 조회).

걱정: 화면에 박힌 자막이 고유명사·숫자 받아쓰기를 도왔다면, 음성만 넘길 때 그 도움이 사라진다.

## 조건

- 모델 `gemini-3.8-flash`(현행과 같음), 같은 프롬프트(음성만), 온도 0, 후보당 1회.
- 입력: `uvx yt-dlp -f bestaudio -x --audio-format mp3 --audio-quality 64K` 로 받은 mp3 를 인라인으로.
- 도구: `scripts/eval-gemini-transcript.ts <영상> gemini-3.8-flash --audio=<파일>`.
- 표본: 26·33번과 같은 한국어 6편. 기준선은 운영 DB 문단(= 현행 방식, 유튜브 주소 입력).

## 통과 기준 (측정 전 고정 — 22번 A~G 그대로)

A 실행 STOP · B 종결 구두점 · C 시각 파싱 · D 시각 정합(대조 50%↑, 중앙값 5초↓) ·
E 글자 수 현행의 85%↑ · F 혼입 0 · G 처리 시간 길이의 25%↓(내려받기 시간은 따로 적는다).

## 정확도 대조 (측정 전 고정)

현행과 다르게 적힌 구간 중 **숫자·영문·고유명사가 들어간 구간**을 따로 뽑아 사용자가 듣고 판정한다.
화면 자막의 도움이 사라졌다면 여기서 드러난다.

## 선정 규칙

1. A~G 6편 통과.
2. 청취 판정에서 현행보다 틀린 곳이 뚜렷하게 많으면 채택하지 않는다(품질이 비용에 앞선다, 33번과 같음).
3. 통과하면 **로컬 등록에서만** 음성 입력을 쓴다. 배포는 그대로.
