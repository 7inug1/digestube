# STT (음성 전사)

상태: 진행 중 — 직접 측정 3/5(mlx-whisper·Groq·유튜브자막)

> **TLDR**: STT 후보 20개 중 17개가 자격을 통과했고, mlx-whisper·리턴제로·Groq·Naver Clova·유튜브자막 5개를 1차 테스트 대상으로 확정했다. 우리 콘텐츠로 직접 돌려 mlx-whisper 4.14%, Groq 4.21%, 유튜브자막 6.34%를 확인했다(전부 잠정치). 참고했던 벤치마크는 경쟁 제품인 리턴제로 자사가 발행한 것이라 각주로만 남기고, 최종 판단은 우리 콘텐츠로 직접 측정한 결과로만 내린다.

## 후보 (17개, 카테고리별)

**로컬 오픈소스**
- Whisper 원본: OpenAI가 만든 기본 구현체(PyTorch)
- mlx-whisper: Apple Silicon(M시리즈 칩)에 맞춰 최적화한 버전(Whisper와 같은 가중치)
- faster-whisper: CTranslate2 엔진으로 다시 짜서 NVIDIA GPU에서 빠르게 돌리는 버전(Whisper와 같은 가중치)
- whisper.cpp: C++로 포팅해서 CPU에서도 가볍게 돌아가는 버전(Whisper와 같은 가중치)
- Qwen3-ASR: 알리바바 Qwen팀의 오픈소스 모델, 한국어 포함 30개 언어 지원. 2026년 1월 출시라 아직 생태계·툴링이 Whisper·NVIDIA NeMo만큼 성숙하지 않고, 공개된 벤치마크도 깨끗한 오디오 기준이라 실제 콘텐츠에서 검증이 더 필요함
- Meta MMS(facebook/mms-1b-all): 한국어 포함 1,162개 언어를 지원하는 오픈소스 모델

**클라우드 해외**
- OpenAI Whisper API: OpenAI가 자기 서버에서 Whisper를 대신 돌려주는 유료 API
- Groq: Groq가 자체 개발한 고속 AI 칩(LPU)으로 Whisper를 호스팅해 저렴하고 빠르게 제공하는 서비스
- Google: 구글 클라우드 음성인식 API(Speech-to-Text v2 / Gemini)
- Azure: 마이크로소프트 클라우드 음성인식 API
- AWS Transcribe: 아마존 클라우드 음성인식 API
- Deepgram: 음성인식 전문 스타트업의 API, 실시간 스트리밍에 강점
- AssemblyAI: 99개 언어 지원 주장, 시간당 $0.15~0.21. 한국어 포함 여부·정확도는 미확인
- Speechmatics: 56개 이상 언어 지원 주장, 시간당 약 $0.13(배치). 한국어 포함 여부·정확도는 미확인

**클라우드 국내**
- Naver Clova Speech: 네이버클라우드의 한국어 특화 음성인식 API
- 리턴제로: 국내 스타트업이 Whisper를 한국어 데이터로 파인튜닝해서 만든 API(VITO Speech)

**기존 방식(비교 대상)**
- 유튜브 자동자막: 이미 모든 영상에 딸려있음, 비용 0, 처리 시간 0. 기존 판단 기록엔 "비교 기준선"으로만 취급했는데, 처음부터 다시 하는 거면 이것도 똑같이 경쟁시켜서 다른 후보들이 실제로 이겨야 자리를 대체할 자격이 생긴다. CER 10.10%(우리 실측), 뜻이 뒤집히는 오역 사례도 확인된 적 있음("우물이 하나밖에 없다"→"꼬물이 1 박 없다").

**어떻게 골랐나**: 카테고리(로컬 오픈소스·해외 클라우드·국내 클라우드)를 먼저 정하고 각 칸을 채웠다.

제외: Kakao(카카오엔터프라이즈의 기업용 커스텀 STT라 가격이 영업 문의로만 나옴, 비공개), NVIDIA Parakeet/Canary(Parakeet 다국어판(TDT v3)도 유럽 25개 언어까지만 지원, 한국어 없음. Canary는 벤치마크가 전부 영어 데이터셋 기준이라 한국어 지원 여부 확인 안 됨 — 둘 다 제외).

## 발견 1 — 비용은 변별력이 없었다

실제 가격을 조사하니 전부 시간당 0~2,000원대였다. "가입·과금 부담" 때문에 로컬 Whisper를 택했다는 기존 판단 근거가 있었는데, 리턴제로도 10시간 무료를 제공한다. 비용이 실제 장벽이 아니었다.

## 발견 2 — 참고 벤치마크의 출처 문제

정확도는 **CER(Character Error Rate)**로 비교했다. 정답 글자 수 대비 몇 글자를 고쳐야(바꾸기·지우기·넣기) 정답과 같아지는지의 비율이고, 편집 거리(Levenshtein distance)로 계산한다. 낮을수록 정확하다.

| 기술 | CER |
|---|---:|
| 리턴제로 | 5.91% |
| Naver Clova | 7.52% |
| Azure | 10.88% |
| AWS | 11.11% |
| Whisper(로컬/Groq/API 공통, 같은 가중치) | 11.39% |
| Google | 11.50% |
| Deepgram | 21.02% |

출처: [rtzr/Awesome-Korean-Speech-Recognition](https://github.com/rtzr/Awesome-Korean-Speech-Recognition)(AI-Hub 공개 데이터셋 기준, 도메인별 3,000문장 샘플링). 이 저장소를 만든 rtzr은 리턴제로 회사 자신이다. 자기 제품이 1등으로 나오는 벤치마크를 자기가 공개한 것이다. 방법론(공개 데이터셋, 코드 공개)은 투명하지만, 참고용으로만 쓰고 최종 판단 근거로는 쓰지 않는다.

기존 판단 기록의 "로컬 Whisper CER 6.88%"는 우리 영상("컴공")으로 직접 측정한 값이다. "11.34%"는 이 rtzr 벤치마크에서 그대로 인용한 값으로 보인다. 서로 다른 측정을 같은 것으로 착각하고 비교했었다.

## 발견 3 — 사전 판단과 사후 확인은 구분해야 한다

**사전(ex-ante)은 결과를 모르는 시점에 알 수 있었던 정보만으로 내리는 판단이고, 사후(ex-post)는 결과를 이미 본 뒤에 "그때 이래서 옳았다"고 정당화하는 것이다.** 복권으로 치면, 사기 전에 당첨 확률만 보고 사는 게 사전 판단이고, 당첨되고 나서 "그때 살 만했다"고 말하는 건 사후 확인이다. 둘을 섞으면 안 된다.

"커스터마이즈 가능성"(오픈소스라 버그를 직접 수정할 수 있다)을 가중치 1순위로 놨었는데, 이건 버그를 이미 겪어본 뒤에야 알 수 있는 사실이다. 처음 고르는 시점엔 몰랐던 정보라 사전 기준에 넣을 수 없다. 커스터마이즈를 빼고 정확도와 비용만으로 다시 채점하면 리턴제로가 1위(0.88), 로컬 Whisper는 2위(0.73)가 된다. 사전 기준만으로는 리턴제로가 더 합리적인 선택이었을 것이다.

"환각(반복) 버그를 직접 고쳤다"는 강점도 다시 봐야 한다. 이 버그 자체가 Whisper 특유의 구조적 약점(디코더 기반 자기회귀 모델의 알려진 문제, 논문으로 확인됨)이다. 다른 벤더는 애초에 이 버그가 없었을 수도 있다. "고칠 수 있어서 좋았다"는 사후에는 맞는 말이지만, 처음부터 그걸 노리고 로컬 Whisper를 고른 건 아니었다.

## 직접 측정 결과

우리 콘텐츠(세바시 "완벽주의" 영상, 821초)로 직접 잰 CER이다. 정답은 이 영상에 실제로 달린 사람 자막(`fGNGKCz60NE.ko.vtt`), 측정 스크립트는 `server/cer_test.py`.

| 후보 | CER | 속도 |
|---|---:|---:|
| mlx-whisper(whisper-large-v3-turbo, 로컬) | 4.14% | 5.4배속 |
| Groq(whisper-large-v3, 클라우드) | 4.21% | 167배속 |
| 유튜브 자동자막(같은 영상, 재측정) | 6.34% | 즉시(이미 존재) |

"컴공" 영상에서 쟀던 6.88%보다 낮게 나왔다 — 영상 하나로만 잰 숫자는 콘텐츠 종류(강의체 vs 강연체)에 따라 달라질 수 있다는 뜻이라, 여러 영상으로 재는 게 왜 필요한지 다시 확인된 셈이다. 유튜브 자동자막도 예전 판단 기록의 10.10%(다른 영상 기준)보다 이 영상에서는 낮게 나왔다 — 역시 영상마다 다르다는 같은 패턴이다.

**세 숫자 다 잠정치다.** 정답 자막을 사람이 직접 듣고 대조하는 검증(`03-cer-videos.md` 3단계)을 아직 안 거쳤다. 실제로 이 영상은 앞 30초에 자막이 안 달린 구간(예고편)이 있어서, 그 구간이 오류로 잘못 잡혔을 가능성이 있다. 3단계 검증을 마친 뒤 이 숫자를 다시 확정한다.

**로컬과 Groq는 사실 다른 모델을 쓰고 있었다.** 원본 프로젝트는 로컬에서 `whisper-large-v3-turbo`, Groq에서 `whisper-large-v3`를 호출하면서 코드 주석에는 "같은 모델"이라고 적어놨다. turbo는 속도를 위해 별도로 만들어진 변형이라 원본과 같은 모델이 아니다. 이번 측정은 원본 설정을 그대로 따랐고, 결과적으로 두 모델의 CER 차이는 0.07%p로 매우 작았다(4.14% vs 4.21%). 대신 속도는 Groq가 31배 빨랐다(167배속 vs 5.4배속).
