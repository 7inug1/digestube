# 4번 자리(목차) 재실행 — 통과 기준을 먼저 적는다

작성 2026-09-12, **실행 전**. 09·11번 문서의 1차 비교를 이어받는다.

## 왜 다시 하나

2026-09-09 에 후보 6종을 26문단에 돌렸다(`data/evals/2026-09-09*`). 그런데 두 가지가 걸린다.

1. **통과 기준을 측정 뒤에 적었다.** 그래서 "비교했다"까지만 쓸 수 있고 "비교해 선정"은 쓸 수 없다.
2. **조건이 달랐다.** Sonnet 5 는 `temperature` 를 거부해(HTTP 400) 온도 없이 돌았고 나머지는 0 이었다.

## 실패 정의

목차가 실패하면 이렇게 보인다. 원문에 없는 말이 제목에 올라가고, 사용자는 그 문단을 열기 전까지 모른다.

## 후보 (3종)

1차에서 통과율 상위였던 셋만 남긴다. 새 후보를 넣지 않는다.

| 후보 | 1차 통과 | 1차 평균 응답 |
|---|---:|---:|
| Claude Sonnet 5 (현행) | 25/26 | 1894ms |
| Claude Haiku 4.5 | 24/26 | 1310ms |
| qwen3.8-27b (Groq) | 24/26 | 479ms |

## 조건 (전부 동일)

- **온도를 아무 후보에도 주지 않는다.** 1차의 조건 차이를 없애려는 것이다. 그래서 1차 숫자와 직접 비교하지 않는다.
- 같은 프롬프트(1차와 동일), 같은 문단, 후보당 2회 실행(흔들림 측정).
- 표본: 현재 DB 문단에서 영상별로 고르게 뽑은 **30문단**. 출력을 보기 전에 manifest 에 고정한다.
- 출력 토큰 상한은 기존 연동과 같다(Anthropic 300, Groq 800). 공급업체가 다르므로 "모델 자체 속도" 비교가 아니다.

## 통과 기준 (측정 전 고정)

문단 하나의 **통과** = JSON 파싱됨 + `label` 1~25자 + `quote` 가 문단 원문에 글자 그대로 있음(공백·구두점 무시).

**선정 규칙**

1. 통과율이 가장 높은 후보를 고른다.
2. 통과율 차이가 **2%p 이내면 동률**로 본다. 동률이면 ① 흔들림(2회 결과 불일치)이 적은 쪽 ② 평균 응답이 빠른 쪽 순으로 고른다.
3. **현행 Sonnet 5 유지가 기본이다.** 다른 후보가 위 규칙으로 이겨야 교체한다.
4. 통과율이 90% 미만인 후보는 선정 대상에서 뺀다.

## 미리 적어두는 한계

- 자동 인용 대조는 제목이 **사실인지**를 보증하지 않는다. 원문에 있는 문장을 옮겼는지만 본다.
- 제목 품질(핵심 대표·구체성)은 사람 채점 영역이고 이번 실행에 넣지 않는다.
- 전사가 Gemini 로 바뀌어 문단 글이 달라졌다. 1차(native 전사)와 같은 표본이 아니다.
