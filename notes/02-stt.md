# STT (음성 전사)

상태: 진행 중 — 다음 액션 정해짐

> **TLDR**: STT 후보 12개 중 로컬 Whisper·리턴제로·Groq·Naver Clova 4개를 실제 테스트 대상으로 확정했다. 참고했던 벤치마크는 경쟁 제품인 리턴제로 자사가 발행한 것이라 각주로만 남기고, 최종 판단은 우리 콘텐츠로 직접 측정한 결과로만 내리기로 했다.

## 후보 (12개, 카테고리별)

- 로컬: Whisper 원본, mlx-whisper, faster-whisper, whisper.cpp
- 클라우드 해외: OpenAI Whisper API, Groq(whisper-large-v3 호스팅), Google, Azure, AWS Transcribe, Deepgram
- 클라우드 국내: Naver Clova Speech, 리턴제로

제외: 유튜브 자동자막(후보 아니라 비교 baseline), Kakao·AssemblyAI·Speechmatics(정보 부족으로 판단 보류).

## 발견 1 — 비용은 변별력이 없었다

실제 가격을 조사하니 전부 시간당 0~2,000원대였다. "가입·과금 부담" 때문에 로컬 Whisper를 택했다는 기존 판단 근거가 있었는데, 리턴제로도 10시간 무료를 제공한다. 비용이 실제 장벽이 아니었다.

## 발견 2 — 참고 벤치마크의 출처 문제

정확도는 **CER(Character Error Rate)**로 비교했다. 정답 글자 수 대비 몇 글자를 고쳐야(바꾸기·지우기·넣기) 정답과 같아지는지의 비율이고, 편집 거리(Levenshtein distance)로 계산한다. 낮을수록 정확하다.

| 기술 | CER |
|---|---:|
| 리턴제로 | 5.91% |
| Naver Clova | 7.52% |
| Azure | 10.88% |
| AWS | 11.11% |
| Whisper(로컬/Groq/API 공통, 같은 가중치) | 11.39% |
| Google | 11.50% |
| Deepgram | 21.02% |

출처: [rtzr/Awesome-Korean-Speech-Recognition](https://github.com/rtzr/Awesome-Korean-Speech-Recognition)(AI-Hub 공개 데이터셋 기준, 도메인별 3,000문장 샘플링). 이 저장소를 만든 rtzr은 리턴제로 회사 자신이다. 자기 제품이 1등으로 나오는 벤치마크를 자기가 공개한 것이다. 방법론(공개 데이터셋, 코드 공개)은 투명하지만, 참고용으로만 쓰고 최종 판단 근거로는 쓰지 않는다.

기존 판단 기록의 "로컬 Whisper CER 6.88%"는 우리 영상("컴공")으로 직접 측정한 값이다. "11.34%"는 이 rtzr 벤치마크에서 그대로 인용한 값으로 보인다. 서로 다른 측정을 같은 것으로 착각하고 비교했었다.

## 발견 3 — 사전 판단과 사후 확인은 구분해야 한다

**사전(ex-ante)은 결과를 모르는 시점에 알 수 있었던 정보만으로 내리는 판단이고, 사후(ex-post)는 결과를 이미 본 뒤에 "그때 이래서 옳았다"고 정당화하는 것이다.** 복권으로 치면, 사기 전에 당첨 확률만 보고 사는 게 사전 판단이고, 당첨되고 나서 "그때 살 만했다"고 말하는 건 사후 확인이다. 둘을 섞으면 안 된다.

"커스터마이즈 가능성"(오픈소스라 버그를 직접 수정할 수 있다)을 가중치 1순위로 놨었는데, 이건 버그를 이미 겪어본 뒤에야 알 수 있는 사실이다. 처음 고르는 시점엔 몰랐던 정보라 사전 기준에 넣을 수 없다. 커스터마이즈를 빼고 정확도와 비용만으로 다시 채점하면 리턴제로가 1위(0.88), 로컬 Whisper는 2위(0.73)가 된다. 사전 기준만으로는 리턴제로가 더 합리적인 선택이었을 것이다.

"환각(반복) 버그를 직접 고쳤다"는 강점도 다시 봐야 한다. 이 버그 자체가 Whisper 특유의 구조적 약점(디코더 기반 자기회귀 모델의 알려진 문제, 논문으로 확인됨)이다. 다른 벤더는 애초에 이 버그가 없었을 수도 있다. "고칠 수 있어서 좋았다"는 사후에는 맞는 말이지만, 처음부터 그걸 노리고 로컬 Whisper를 고른 건 아니었다.
