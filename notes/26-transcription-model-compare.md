# 전사 모델 비교 — 3.5 / 3.6 / 3.8 flash

작성 2026-09-13, **실행 전**.

## 왜

2번 자리를 Gemini 로 바꿀 때 `gemini-3.5-flash` 하나로만 쟀다([22번](22-transcription-gemini.md)).
그런데 최신 모델이 **더 싸다**. 실측 토큰(입력 38k · 출력+사고 10.9k, 6.9분 영상) 기준 단가는

| 모델 | 입력 /1M | 출력 /1M | 영상 1편 |
|---|---|---|---|
| 3.5-flash (현행) | $1.50 | $9.00 | 약 $0.155 |
| 3.6-flash | $0.75 | $3.75 | 약 $0.063 |
| 3.8-flash | $0.75 | $3.75 | 약 $0.063 |

품질이 같다면 현행이 가장 비싼 선택이 된다. 그래서 같은 조건으로 셋을 나란히 잰다.

## 조건

- 같은 프롬프트(음성만), 온도 0, 같은 한국어 6편, 후보당 1회.
- 22번 카드의 통과 기준 A~G 를 그대로 쓴다. 기준을 새로 만들지 않는다.
- 비교 대상은 **음성 전사 품질·시각 정합·시간·비용**. 화면 글자는 이번에 안 받는다([25번](25-screen-text.md)).

## 통과 기준 (측정 전 고정)

1. 22번 A~G 를 통과한 후보만 대상. 단 D(시각 정합)는 native 기준선이 무너진 2편
   (`PlawByYfV8k`·`NtHSSWC04Do`)에서 자동 판정이 안 되므로, 그 2편은 **모델 간 교차 일치**로 본다.
2. 통과한 후보 중 **영상 1편 단가가 가장 싼 쪽**을 고른다.
3. 단가가 같으면(3.6 vs 3.8) 처리 시간이 짧은 쪽.
4. 품질 차이가 드러나면 가격보다 품질이 앞선다 — 구체적으로, 6편 중 통과 편수가 적은 후보는 탈락.

## 한계

- 후보당 1회씩이라 실행 간 흔들림은 보지 않는다.
- 비용은 실측 토큰 × 공시 단가의 추정이다. 실제 청구서와 다를 수 있다.
- 한국어 6편이다. 영어는 재지 않는다.

## 추가: Supadata `generate` 를 같은 표본에 넣는다 (2026-09-13, 실행 전)

어제 3회 실패(127초 524)로 후보에서 뺐는데 **오늘 다시 되는 것을 확인했다**(2.7분 영상 69.3초, HTTP 200, 2크레딧).
그래서 "막혀서 바꿨다"가 아니라 **같은 기준으로 비교**할 수 있게 됐다.

비교 대상: `Supadata generate` vs `gemini-3.8-flash`. 표본은 같은 한국어 6편.

### 통과 기준 — 22번 A~G 를 그대로 쓴다

새 기준을 만들지 않는다. D(시각 정합)는 native 기준선이 무너진 2편에서 자동 판정이 안 되므로
그 2편은 후보끼리의 교차 일치로 본다.

### 오인식 판정 (측정 전 고정)

두 전사문이 갈리는 구간만 뽑아 판정한다. 전체를 사람이 듣지 않는다.

1. 두 전사문을 정렬해 **다르게 적힌 구간**을 추출한다.
2. 각 구간을 제3 모델에게 영상의 해당 시각과 함께 주고 **어느 쪽이 맞는지** 고르게 한다.
   판정 모델은 후보와 다른 것을 쓴다. 같은 모델에게 자기 답을 고르게 하지 않는다.
3. **집계는 "맞음/틀림/판정 불가" 세 갈래.** 판정 불가를 어느 쪽 점수로도 세지 않는다.

**선정 규칙**: 오인식이 적은 쪽을 고른다. 차이가 표본의 10% 이내면 동률로 보고, 동률이면
처리 시간이 짧은 쪽 → 무료로 처리 가능한 양이 많은 쪽 순.

### 미리 적어두는 한계

- generate 는 Whisper 계열이라 소리만 듣고, Gemini 는 화면도 본다. **같은 조건이 아니다.**
  이 비교는 "같은 입력(유튜브 주소)으로 무엇을 돌려주나"를 보는 것이지 음성 인식 알고리즘 비교가 아니다.
- 제3 모델 판정도 기계 판정이다. 사람 검수가 아니다.
