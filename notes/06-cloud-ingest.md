# 클라우드에서 새 영상 추가(`/ingest`) 가능하게 만들기

상태: 조사 중

> **TLDR**: 유튜브는 데이터센터 IP를 몇백 번 요청 안에 감지해서 차단하고, 레지덴셜(가정용) IP는 수만 번까지 허용한다 — 이건 업계 전체가 겪는 구조적 문제고, 오디오를 받든 자막만 긁든 방식을 바꿔도 똑같이 막힌다. 실제 서비스들은 브라우저 확장 프로그램(클라이언트가 직접 접근)이나 유료 레지덴셜 프록시로 우회한다. 우리도 이 두 방향 중 하나를 골라야 한다.

## 왜 이게 STT 후보 문제가 아닌가

STT 모델을 뭘 고르든 클라우드에서 다 돌아간다(Groq·Deepgram·Naver Clova 등은 이미 API라 어디서든 호출 가능). 진짜 막힌 건 그 앞 단계 — 유튜브에서 오디오 자체를 받아오는 것. 이건 STT 선택과 무관한 별개 문제다.

## 확인된 사실

**차단 기준은 방식이 아니라 IP다.** 오디오 다운로드(yt-dlp)든 자막 전용 스크래핑(`youtube-transcript-api` 등)이든, 데이터센터 IP(AWS/GCP/Azure)에서 요청하면 몇백 번 안에 걸린다. 레지덴셜 IP는 수만 번까지 버틴다. 방식을 바꿔서 우회되는 문제가 아니다.

**실제 서비스들의 대응**:
- Supadata: 유튜브 자막을 1순위로 쓰고, 없을 때만 Whisper로 보완. 프록시 방식은 비공개.
- 검색 상위에 뜨는 유튜브 요약 도구 다수가 **브라우저 확장 프로그램**으로도 나와있다(Chrome Web Store에 여럿). 확장 프로그램은 유튜브 페이지에 직접 접근 권한이 있어서 이 차단 자체를 안 만난다.
- **릴리스(Lilys AI)는 확장 프로그램도 있지만 핵심은 웹사이트+공개 API다** — URL만 붙여넣으면 서버가 직접 처리한다(`lilys.ai/api`). 즉 **서버 쪽에서 이 차단 문제를 실제로 풀어낸 사례가 있다는 뜻**이다. 내부 구현은 비공개지만, API까지 파는 규모의 회사면 유료 레지덴셜 프록시(GB당 몇천 원 수준) 정도는 감당할 여력이 있다 — 확장 프로그램은 UX 편의 옵션이고 핵심 인프라는 서버 쪽 유료 프록시일 가능성이 높다.
- 업계에서 언급되는 우회 방법 체인: PO Token 제공 서버, Cobalt(셀프호스팅 다운로더), Piped·Invidious(유튜브 대체 프론트엔드), GitHub Actions 러너(매번 다른 IP로 뜸), Cloudflare Workers, SOCKS5 프록시. 어느 하나도 100% 안정적이지 않아 여러 개를 순서대로 시도하는 방식을 권장한다는 게 업계 공통 의견이다.

**레지덴셜 프록시 실제 가격**(2026년 기준):
| 업체 | 가격 |
|---|---:|
| DataImpulse | 레지덴셜 $1/GB, 모바일 $2/GB |
| IPRoyal | 레지덴셜 $7.35/GB |
| Oxylabs | 레지덴셜 $7/GB |

영상 하나 오디오가 보통 10~30MB 안팎이니, 저렴한 쪽(DataImpulse)이면 영상 100개 받아도 3GB 안팎 — 몇천 원 수준이다.

## 이미 시도하고 실패한 것 (원래 프로젝트 기록)

Tor IP 우회, 주거용 IP, 로그인 쿠키 — 세 가지 다 시도했으나 실패, 로컬 처리로 최종 확정됐다. 정확히 어떤 방식·어떤 품질의 프록시였는지는 원본 기록에 세부가 남아있지 않다.

## 새로 고려할 후보

1. **유료 레지덴셜 프록시** (DataImpulse 등) — 이전 시도가 무료/저품질 프록시였을 가능성이 있어 재시도 가치 있음. 릴리스(Lilys AI)가 확장 프로그램 없이 웹+API만으로 작동한다는 게 이 방향이 실제로 통한다는 정황 증거임
2. **PO Token 제공 서버** — 이미 `bgutil-ytdlp-pot-provider`(Node.js)를 로컬에서 써본 적 있음, 클라우드에 같이 띄우는 방식
3. **클라이언트(사용자 브라우저)에게 위임** — 브라우저 확장 프로그램(설치 필요, 안정적) 또는 탭 캡처 API(설치 불필요, 느리고 매번 권한 필요). iframe으로 오디오 가로채기는 CORS로 불가능함을 확인함.
4. **GitHub Actions 러너를 다운로드 전용으로 사용** — 매 실행마다 새 IP를 받아서, 차단 누적이 안 될 가능성
5. **로컬 유지 + 정직하게 설명** — "이건 업계 전체가 겪는 구조적 한계"라는 근거(이 노트)를 그대로 답변에 씀
