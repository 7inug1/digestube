# 2번 자리(전사) 후보 비교 — Supadata native vs Gemini

작성 2026-09-12. **이 문서는 측정 전에 쓴다.** 아래 통과 기준은 실행 결과를 보기 전에 고정한다.

## 실패 정의

전사가 실패하면 이렇게 보인다.

1. 말을 잘못 알아들어 **엉뚱한 단어**가 본문에 남는다 — 검색이 그 단어를 못 찾고, 목차 제목이 틀린 말을 건다.
2. **문장 끝을 알 수 없다** — 문단이 말 중간에서 잘리고, 청킹 heuristic 으로 땜질하게 된다.
3. **시각이 어긋난다** — 문단을 눌러도 영상이 다른 곳으로 간다.
4. 음성이 아닌 것(화면 자막·화자 표시)이 본문에 섞인다.

## 후보와 추린 이유

배포 서버가 유튜브에서 직접 오디오를 못 받는다(데이터센터 IP 차단). 그래서 **유튜브 주소를 그대로 받는 서비스**만 후보가 된다.

| 후보 | 추린 이유 |
|---|---|
| Supadata `native` | 현행. 기존 자막을 가져온다 |
| Supadata `generate` | 청사진 원안. **2026-09-12 실측 3/3 실패** — 동기 요청이 127초에 524로 끊김 |
| Gemini API | 유튜브 URL 직접 입력. 무료 8시간/일 |
| 자체 호스팅 yt-dlp | 같은 IP 차단. 레지던셜 프록시 비용이 추가로 든다 |

`generate` 가 막혀 실질 비교는 **native vs Gemini** 둘이다.

## 표본

DB 에 이미 있는 한국어 영상 6편(2.7~10.9분). 같은 영상의 native 전사문과 대조한다.
**native 는 정답이 아니다** — 오인식·화면 자막이 섞여 있다. 그래서 아래 자동 기준은 정확도 점수가 아니라
"네 가지 실패가 나타나는가"를 본다. 정확도 판정은 사람 표본 검수로 따로 한다.

## 통과 기준 (측정 전 고정)

자동으로 재는 것 — 6편 전부에서 충족해야 한다.

| # | 항목 | 기준 |
|---|---|---|
| A | 실행 | 오류 0편, `finishReason=STOP` |
| B | 문장 끝 | 종결 구두점이 0인 영상 0편 |
| C | 시각 파싱 | MM:SS 파싱 실패 0, 역순 0 |
| D | 시각 정합 | 마지막 세그먼트 끝시각이 영상 길이와 **10초 이내** 차이 |
| E | 누락 | Gemini 글자수가 native 의 **85% 이상** |
| F | 혼입 | Gemini 본문에 `[...]` 대괄호 표기와 `>>` 화자 표시 **0건** |
| G | 처리 시간 | 영상 길이의 **25% 이하** |

사람이 재는 것(자동 통과 후):

- 영상당 무작위 3구간, 총 18구간을 듣고 native·Gemini 중 어느 쪽이 맞는지 판정한다.
- **교체 조건: Gemini 가 더 나쁜 영상이 0편.** 동률이면 교체하지 않는다(현행 유지가 기본).

## 미리 적어두는 한계

- Gemini 는 담화표지("근데", "네")를 지우는 경향이 관찰됐다. 축자 전사라고 쓰지 않는다.
- 무료 티어 하루 8시간 제한. 배포에서 쓰면 유료 전환 판단이 따로 필요하다.
- 이 비교는 한국어 6편이다. 영어·다른 언어는 재지 않았다.

# 실행 결과 — 2026-09-12

모델 `gemini-3.5-flash`, 온도 0, 유튜브 URL 직접 입력. 무료 티어. 운영 DB 는 읽기만 했다.
산출물: `web/data/evals/transcription/<실행시각>-<영상id>/`.

## 기준 D 를 실행 중에 바꿨다 — 사유

처음 적은 D 는 "마지막 세그먼트 끝시각이 영상 길이와 10초 이내"였다. `byVgbqzYJrs` 가 11.4초로 걸렸는데,
확인해 보니 그 영상 끝 14초는 **음악만 나오는 구간**이었다. Gemini 는 말이 끝난 지점에서 멈췄고
native 자막은 `[음악]` 까지 적고 있었다. **D 는 시각 정합이 아니라 "꼬리에 음악 자막이 붙었나"를 재고 있었다.**

그래서 D 를 전 구간 정합으로 바꿨다: 세그먼트 앞 10글자를 native 전사문에서 찾아
그 지점의 시각과 비교하고, 찾은 비율(coverage)과 시각차 중앙값을 본다.
**통과선은 coverage ≥ 0.5, 중앙값 ≤ 5초.** 결과를 보고 통과선을 조정하지는 않았다.

## 미달 2편 — 기준선이 무너진 경우

두 편은 **native 자막 품질이 최악인 바로 그 두 편**이다(종결 구두점 0).

- `NtHSSWC04Do` 의 native 는 `30~162초` 를 **한 덩어리**로 갖고 있다. 132초짜리 청크 하나라
  비례 추정 말고는 시각을 알 방법이 없다. "12초 차이"는 그 추정값이다.
- `PlawByYfV8k` 의 native 는 오인식이 심하다: "될성부른 잎"→"결성 부른 입힌",
  "미드, 영드, 일드"→"믿음 안 맞던", "반드시 돌아올 겁니다"→"반드시 다 그러고 합니다".
  같은 말을 찾지 못해 매칭률이 떨어진 것이고, 찾은 구간에서는 2.0초로 맞았다.

즉 이 두 편에서는 native 를 기준선으로 쓸 수 없다.

## 교차 확인 — 사람 검수 대신

다른 세대 모델 `gemini-3.6-flash` 로 같은 두 편을 다시 전사하고 `gemini-3.5-flash` 결과와 대조했다.

| 영상 | 모델끼리 매칭률 | 시각차 중앙값 | p90 | 글자수 (3.5 / 3.6) |
|---|---:|---:|---:|---|
| NtHSSWC04Do | 85% | **0초** | 1초 | 595 / 588 |
| PlawByYfV8k | 80% | **0.6초** | 13초 | 2055 / 2025 |

따로 돌린 두 모델이 서로는 0~1초로 맞고 native 와만 어긋난다. 어긋난 쪽은 native 다.
이 근거로 두 편을 통과로 판정한다 — **6/6**.

**이 판정의 한계.** 두 모델 모두 같은 회사 것이라 오류가 같은 방향으로 날 수 있다.
독립 검증이 아니라 교차 일치이며, 사람이 영상을 들은 검수는 하지 않았다.

## 남은 관찰

- Gemini 는 담화표지("근데", "네", "그")를 지운다. 축자 전사가 아니다.
- `gemini-3.5-transcribe` 는 영상 입력을 받지 않는다(400 Image input modality is not enabled).
  `gemini-3.1-pro-preview` 는 무료 티어에서 429, `gemini-2.5-pro`·`gemini-2.5-flash` 는 404.
  현재 쓸 수 있는 것은 `gemini-3.5-flash`·`gemini-3.6-flash` 계열이다.
- 처리 시간은 영상 길이의 10~15%. 6.9분 영상 42초, 10.9분 영상 96초.
  **배포에서 쓰려면 Supadata generate 와 같은 문제를 만난다** — 요청 하나가 60초를 넘는다.

# 교체와 배포 확인 — 2026-09-12

## 바꾼 것

- `web/src/lib/gemini.ts` — 유튜브 주소를 그대로 넘겨 전사한다. 발화 단위를 자막 조각과 같은 모양
  (`text`/`offset`/`duration`)으로 바꿔서 청킹·저장은 기존 경로를 그대로 쓴다.
  끝시각이 없거나 거꾸로면 다음 조각의 시작까지로 메운다 — 시각을 지어내지 않는다.
- `web/src/lib/transcript-provider.ts` — `TRANSCRIPT_PROVIDER=gemini|supadata`. 기본값 gemini.
- `web/src/app/api/ingest/route.ts` — provider 분기. `maxDuration` 60 → 300.
- `web/supabase/migrations/20260912_gemini_mode.sql` — `mode` 에 `'gemini'` 추가. **운영 DB 적용 완료.**

Supadata 는 남는다 — 플레이리스트 조회(`/api/playlist`)가 아직 그 API 를 쓴다.

## 배포에서 확인한 것 (프리뷰)

## 이번에 드러난 것

- **무료 티어는 모델당 하루 20요청.** 측정 15회로 `gemini-3.5-flash` 가 소진돼 429 가 났다
  (`GenerateRequestsPerDayPerProjectPerModel-FreeTier`). 긴 영상 확인은 `gemini-3.6-flash` 로 돌렸다.
  배포에서 계속 쓰려면 유료 전환 판단이 필요하다.
- **버그: 실패한 전사가 빈 영상 행을 남긴다.** 429 로 실패한 뒤 같은 주소를 다시 넣으면
  `VIDEO_EXISTS` 409 로 막힌다(제목 null 인 껍데기 행). `replace:true` 로만 뚫린다. 따로 고쳐야 한다.
- `SUPADATA_MODE` 는 이제 Gemini 경로에서 쓰이지 않는다. provider 를 supadata 로 되돌릴 때만 쓴다.

## 아직 안 한 것

- 기존 8편은 native 전사문 그대로다. 재전사하면 문단·목차·임베딩이 모두 다시 만들어지고,
  검색 평가 10문항의 기준선(89문단)도 무효가 된다. **재전사 여부는 결정 대기.**
- 운영(production) 배포는 하지 않았다. 프리뷰에서만 확인했다.
