# Digestube 이력서 재작성안

아래 본문은 운영 DB 변경과 코드 재배포까지 확인한 뒤 사용할 최종안이다.
현재 로컬 구현·검증과 기존 운영 배포를 구분해서 설명한다.

**Digestube — 유튜브 영상을 목차와 전사문으로 읽는 웹 데모**
개인 프로젝트 · 2026.08–09

- 유튜브 주소를 입력하면 자막을 읽기 좋은 크기로 나누고 목차를 생성해, 내용을 읽거나 자연어로 관련 구간을 찾을 수 있는 웹 데모 개발·배포
- **자막 수집:** 클라우드에서 유튜브 직접 접근이 반복 차단되는 것을 확인해 Supadata로 전환. 배포 환경의 요청 시간 제한을 고려해, 음성 받아쓰기 대신 기존 유튜브 자막을 가져오는 방식 적용
- **목차 생성:** 제목의 근거 문장이 실제 자막에 있는지 확인하고, 확인되지 않으면 한 번 더 생성. 다시 실패하면 원문 첫 문장을 25자 이내로 표시해 목차에서 해당 구간으로 이동할 수 있도록 구현
- **의미 검색:** KURE-v1 임베딩과 Supabase pgvector로 질문과 관련 있는 문단을 찾고, 전사문과 영상 재생 시점을 연결
- **데이터 보호:** 재등록 시 사용자 확인을 거치고 새 자막이 정상적으로 준비된 뒤 기존 데이터를 교체. 수집 방식·응답 언어를 기록하고, 중간 실패 후 목차·검색 준비를 이어서 처리할 수 있도록 구현

Link · https://digestube-v2.vercel.app

## 면접에서 구분할 것

- v2에는 질문에 대한 답변 생성이 없다. 검색과 답변 생성을 혼용하지 않는다.
- 인용문이 원문에 있는지 검사하는 것과 제목이 핵심을 정확히 대표하는지는 다르다.
- Sonnet 5는 잠정 모델이다. 3종 블라인드 자료는 만들었으나 사람 평가는 보류했다.
- 청킹은 문장 끝·길이 기반이다. 4가지 모두를 측정해 재귀 분할이 우승했다는 표현은 쓰지 않는다.
- native 문단 경계와 검색 품질의 확정 평가, 사용자 검증은 남아 있다.
