# 청사진 7자리 — 무엇을 고르는 자리이고 지금 어디까지 왔나

2026-09-12. Codex 가 읽을 문서다. 프레임워크 자체는
[20-development-evidence-framework.md](20-development-evidence-framework.md) 에 있고,
이 문서는 **그 틀로 7자리를 실제로 채점한 결과**다.

## 0. 청사진이 뭔가

파이프라인에서 "고를 게 있는 자리"를 7개로 나눠 둔 표다. 자리마다 라벨이 붙는다.

| 라벨 | 뜻 |
|---|---|
| `재봄` | 아직 안 골랐다. 임시로 하나 박아두고 나중에 다시 고른다 |
| `정함` | 측정하고 골랐다 |
| `제약으로 결정` | 고른 게 아니라 남은 것. 제약이 풀리면 자리가 다시 열린다 |

**7자리는 사용자가 정한다.** 구현 세부(폴더 구조·변수명·CSS·기본키 형식)는 AI 가 정하고 바로 알린다.
멈추고 물어야 하는 조건 셋: ① 데이터 모양이 바뀔 때 ② 숫자나 기준이 생길 때(임계치·지표·모델 선정·프롬프트 규칙)
③ 돈이나 외부 의존이 생길 때.

## 1. 일곱 자리와 현재 라벨

| # | 자리 | 고르는 것 | 지금 박혀 있는 것 | 라벨 |
|---|---|---|---|---|
| 1 | 오디오 추출 | 영상에서 소리를 어떻게 꺼내나 | Supadata 가 통째로 처리 | `제약으로 결정` |

| 3 | 문단 나누기 | 전사문을 어디서 자르나 | recursive splitting + 문장 경계 | `재봄` — **해법 둘로 갈림** |
| 4 | 목차 생성 | 문단마다 제목을 누가 다나 | `claude-sonnet-5` | `재봄` |

`AGENTS.md` 4장이 두 군데 낡았다. 목차를 `Claude Haiku 4.5 (임시)` 로,
저장소를 `결정만, 미구현` 으로 적고 있는데 실제로는 Sonnet 5 가 돌고 있고
Supabase 는 구현·배포까지 끝났다. 고칠 때 같이 고친다.

## 2. 채택한 3단계 (2차 이력서 피드백 원문)

> 먼저 **내 서비스에서 이 컴포넌트가 실패하면 어떤 모습인지**를 적는다.
> 이 실패 정의에서 선정 기준이 나온다.
> 다음으로 그 기준으로 **후보를 두세 개로 추린다.** 리더보드와 벤치마크는 여기까지만 쓰는 도구다.
> 마지막으로 **내 데이터로 측정해 결정한다.** 무엇을 몇 점 이상이면 통과로 볼지는 **측정 전에** 적어 둔다.

핵심은 마지막 문장이다. **통과 기준을 측정 전에 적었는가**가
`기준선 측정`과 `비교 후 채택`을 가르고, 이력서에 쓸 수 있는 문장도 여기서 갈린다.

## 4. 실측 숫자 — 이력서에 그대로 옮길 수 있는 것

### 4-1. 목차 모델 (`web/data/evals/2026-09-09*`)

같은 26문단·같은 프롬프트. 통과 = JSON 유효 + 제목 25자 이내 + **인용문이 원문에 그대로 있음**.

| 후보 | 통과 | 흔들림 | 평균 응답 | 출력 토큰 |
|---|---:|---:|---:|---:|
| Claude Haiku 4.5 | 24/26 | 0 | 1310ms | 70 |
| qwen3.8-27b | 24/26 | 0 | 479ms | 33 |
| Claude Sonnet 5 | 25/26 | 11 | 1894ms | 78 |
| gpt-oss-20b | 22/26 | 0 | 3247ms | 664 |
| gpt-oss-120b | 19/26 | 4 | 2714ms | 590 |
| qwen3.6-27b | 0/26 | 0 | 41904ms | 800 |

**조건이 완전히 같지 않다.** Sonnet 5 는 `temperature` 를 거부해서
(`temperature is deprecated for this model`, HTTP 400) 온도 없이 따로 돌렸다.
흔들림 11 은 그 때문일 수 있고 아닐 수도 있다 — 이 실행으로는 구분이 안 된다.
`qwen3.6-27b` 는 JSON 은 24/26 만들었지만 인용이 0/26 이라 전부 탈락했다.

### 4-2. 검색 기준선 (`web/data/evals/search/runs/2026-09-11T08-10-06-812Z-dev/`)

사용자 검수 질문 10개(답 있음 8, 답 없음 2), 영상 8편·89문단, `top_k=3`, KURE-v1, 임계치 없음.

| 항목 | 결과 |
|---|---:|
| 시간 구간 자동 적중 | 8/8 |
| AI 가 본문 읽고 확인한 명확한 적중 | 7/8 |
| 부분 적중 | 1/8 |
| 올바른 거절 | 0/2 |
| 실행 오류 | 0 |

점수 분포가 겹친다 — 답 있음 1위 0.545~0.667, 답 없음 0.544 와 0.619.
단순 임계치로는 현재 8/10 을 못 넘겨서 제품에 안 넣었다.

## 5. 지금 쓸 수 있는 문장 / 아직 못 쓰는 문장

### 쓸 수 있다 — 목차

> 원문에 없는 제목이 생기는 실패를 막기 위해 인용문이 문단에 글자 그대로 있는지 자동 대조하는 검증을 만들고,
> 후보 6종을 같은 26문단에 돌려 통과율·응답시간·출력량을 비교했다.
> (24/26 · 1310ms · 70토큰 대 25/26 · 1894ms · 78토큰)

여기서 **멈춰야 한다.** "비교해 Sonnet 5 를 선정" 까지 쓰면 거짓이 된다.
통과 기준을 측정 전에 안 적었고, Sonnet 은 조건이 달랐고, 통과율만 보면 Haiku·qwen 이 더 싸고 빠르다.

### 쓸 수 있다 — 검색

> 사용자 검수 질문 10개로 검색 평가를 구성하고, 상위 3개 결과의 정답 구간 포함 여부와
> 무관 질문 거절 여부를 측정해 문맥 누락 1건·무관 결과 반환 2건을 확인했다.

### 못 쓴다 — 임베딩

피드백이 예시로 준 문장은 이 형태다.

> 구어체 전사문 검색이라는 조건으로 후보 N종을 추리고, 영상 N개에서 만든 질문 N건의
> 상위 3위 안 적중률을 비교해 KURE-v1 을 선정

**"비교"에 해당하는 실행이 없다.** KURE-v1 하나만 쟀다. 비교 대상이 0개다.

### 쓸 수 있다 — 제약으로 결정한 자리

> Supadata `mode=generate` 가 작업 번호를 돌려주는 데만 91.8초가 걸려
> Vercel 무료 함수 상한 60초를 넘기는 것을 실측하고, `native` 로 전환한 뒤 동작을 확인했다.

## 6. 빈칸을 채우는 최소 작업 — 이 순서

각 작업은 [20번 문서](20-development-evidence-framework.md)의 실험 카드를 먼저 쓰고 시작한다.
**통과 기준을 실행 전에 카드에 적는다.** 그게 이 프레임워크의 전부다.

1. **임베딩 비교** — 가장 싸고 효과가 크다.
   같은 10문항, 같은 89문단에 KURE-v1 외 후보 2개를 더 돌려 상위 3위 적중률을 비교한다.
   후보를 추린 이유(한국어 구어체·1024차원·무료 추론 가능 여부)를 카드에 적는다.
   이것 하나로 피드백이 예시로 준 문장이 그대로 참이 된다.

2. **문단 나누기 비교** — 이미 해법이 둘 있다. 새로 만들 게 없다.
   같은 전사문에 세 조건(무음만 / 어미만 / 둘 다)을 돌려 **문장 중간에서 끊긴 청크 수**를 센다.
   지표가 이미 정의돼 있어 통과 기준 적기가 쉽다.

3. **목차 재실행** — 여섯을 다시 돌릴 필요는 없다.
   통과 기준을 적은 뒤 상위 2~3개만 **같은 조건으로**(전부 온도 없이) 다시 돌린다.
   그러면 "비교 후 채택" 으로 라벨이 올라가고 이력서 문장도 "선정" 까지 맺을 수 있다.

답변 생성(7번)은 위 셋과 성격이 다르다. 자리를 채우는 구현이지 고르는 문제가 아니다.
이력서에 RAG 의 G 를 쓰려면 필요하지만, 프레임워크로 정당화할 대상은 아니다.
