# 화면 글자를 같이 받을까 — 2026-09-12 측정과 보류 결정

Gemini 는 영상을 프레임째 보고 있다. 지금 프롬프트는 "화면에 뜬 글자는 옮기지 않는다"로
**일부러 버리고** 있다. 이걸 따로 받아 검색에 쓰면 "그 슬라이드 어디였지"가 검색된다.

## 재본 것

`web/scripts/eval-screen-text.ts` — 같은 모델·같은 영상에 프롬프트만 둘로(A 음성만 / B 음성+화면).

| | 뉴스(55eFm5tPCQY) | 토크(8cp0YvSpDA8) |
|---|---|---|
| 입력 토큰 A→B | 45,838 → 45,951 | 37,003 → 37,127 |
| 출력 토큰 A→B | 5,046 → 8,230 | 5,125 → 5,294 |
| 화면 글자 | 214건 5,000자 | 12건 90자 |

**입력은 안 는다.** 프레임은 어차피 보내고 있었다. 늘어나는 것은 출력이다.
화면 글자의 값은 실제로 있다 — "ARR 2억 달러 돌파", "연간 구독 매출 약 3,000억 원" 은
음성에 없고 화면에만 있는 숫자였다.

## 결정: 본 경로에 넣지 않는다

사용자가 기다리는 시간이 곧 두 배가 된다. 전사는 음성만으로 둔다.

화면 글자는 **별도 호출로 분리**하고, 서버가 뒤에서 처리하는 구조(잡 큐)가 생긴 뒤에 얹는다.
그러면 사용자 대기 시간은 그대로고 화면 글자는 나중에 채워진다.

## 그때 다시 볼 것

- 화면 항목이 너무 많이 잡힌다(브이로그성 영상에서도 185~327건). 간판·워터마크까지 긁는다.
  "내용이 있는 글자만" 으로 좁히는 지시가 필요하다.
- 검색에 넣으려면 `chunk` 에 화면 텍스트 자리를 만들고 임베딩 대상에 포함할지 정해야 한다(데이터 모양 변경).
- 사용자에게 "이 영상 강의인가요?" 를 묻는 모달은 필요 없어 보인다. 모델이 이미 영상을 봤다.
