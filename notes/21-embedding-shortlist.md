# 임베딩 재선정 조사·실험 카드 초안

대상: **청사진 6번 임베딩(질문·문단을 벡터로 변환)**. 4번 목차 생성 모델 선정 문서가 아니다. 2026-09-12 KURE-v1과 BGE-M3의 개발 비교를 실행했다. 최종 확인용 새 질문 검수는 남아 있다.

2026-09-12. 상태: 공식 자료 조사 완료, 후보 제안. 자체 비교·운영 변경 미실행.
기준: [개발·평가·이력서 프레임워크](20-development-evidence-framework.md).

## 실패와 선정 조건

한국어 구어체 질문으로 실제 답이 있는 전사문 대목을 찾지 못하거나, 같은 주제의 엉뚱한 문단을 앞에 보여주는 것이 실패다. 영어 전사문도 있으므로 한국어 질문→영어 본문 검색을 별도로 확인한다.

필수 조건 제안: 한/영 검색 적용 가능, 문단 전체 입력 가능(토큰 절단 여부 확인), 문단별 단일 벡터 출력, 사용 조건 확인, 실제 배포 가능한 추론 경로. 1024차원은 필수가 아니라 변경 비용 요소다. 무료 추론도 필수로 가정하지 않는다.

이번 범위는 기존 단일 벡터 검색에서 모델을 비교하는 것이다. 청킹·리랭킹·임계치를 동시에 바꾸지 않는다. 무관 질문 거절은 별도 시스템 문제이며 모델 교체로 해결된다고 가정하지 않는다.

## 재검토 — 실패와 근거 연결 (2026-09-12)

사용자 지적에 따라 아래 최초 후보표의 '기반 모델', '다른 계열'을 단독 선정 이유로 사용하지 않는다. 아래 재검토가 최초 제안보다 우선한다. 후보가 개선할 가능성과 실제로 개선했다는 증거는 다르며, 기존 모델보다 우수함을 미리 증명해야만 비교 후보가 되는 것은 아니다.

### 원본 결과에서 확인한 것

- Q01·Q02: 한국어 질문으로 영어 정답 본문을 1위에서 찾았다. 언어 간 검색은 제품 요구이지만 현재 확인된 실패라고 쓰지 않는다.
- Q07·Q08: 정답 본문이 2위이고 1위는 요청한 답을 담지 않았다. '같은 주제의 다른 문단보다 실제 정답을 먼저 찾기'는 모델 비교로 검토할 수 있는 관측된 문제다. 다만 기존 top-3 기준에는 성공이므로 top-1/MRR은 다음 실험의 진단 지표로 사전에 추가해야 한다. 사후에 기존 합격 기준을 바꾸지 않는다.
- Q03: 설명이 두 문단으로 갈리고 뒤 문단이 검색되지 않았다. 문단 경계와 검색 순위가 함께 영향을 줄 수 있으며 모델만의 실패로 확정하지 않는다.
- Q09·Q10: 거절 장치가 없는 top-3 검색이 결과를 반환했다. 다른 임베딩 모델만으로 거절 기능이 생기지 않는다.
- 17.342초 첫 요청은 전체 검색 시간이다. 임베딩 모델만의 지연으로 단정할 수 없다.

### 외부 근거에 따른 후보 역할

| 후보 | 실패 해결 가능성의 근거 | 주장할 수 없는 것 | 재검토 결론 |
|---|---|---|---|
| KURE-v1 | 한국어 query/document/hard-negative 데이터로 학습하고 한국어 문서 검색 평가를 제공. 비슷하지만 정답이 아닌 문서 구분이라는 과제에 연결됨 | 자막 오인식·구어체 또는 Q07/Q08을 확실히 해결한다는 보장 | 현재 기준선이자 한국어 검색 후보로 타당 |

자료는 개발자 학습 설명·평가이며 독립적인 우리 서비스 검증이 아니다. KURE 카드의 한국어 평가도 문서 검색 위주여서 전사문 오류 견딤을 입증하지 않는다. Qwen 표는 해당 개발자의 고정 시점 평가이지 현재 전체 모델 순위가 아니다.

근거:
- https://huggingface.co/nlpai-lab/KURE-v1 — Training Data, Benchmark Datasets, Results
- https://huggingface.co/BAAI/bge-m3 — Evaluation: MIRACL, MKQA
- https://huggingface.co/Qwen/Qwen3-Embedding-0.6B — Evaluation: MTEB (Multilingual), Retri. 열
- https://qwenlm.github.io/blog/qwen3-embedding/ — 학습 및 검색 과제 설명

BGE 모델 카드의 MKQA 스크립트 링크는 이번 접근에서 404였다. 평가 종류는 카드에서 확인했지만 스크립트 재현을 완료했다고 쓰지 않는다.

**현재 결정:** KURE와 BGE는 외부 검색 평가에 기반한 비교 후보, Qwen은 한국어·교차언어 세부 근거가 덜 직접적인 조건부 후보로 둔다. 반드시 세 개를 채울 필요는 없다. 실제 비교 전에는 질문별 의미 정답 판정과 제품의 top-1/top-3 요구를 고정한다. 가장 먼저 원인 분리와 운영 경로를 확인하며 모델 교체는 하지 않는다.

## 보류한 대안

- **KURE-v2:** 공식 카드 기준 한국어·영어 multi-vector/MaxSim 모델. 현재 문단당 단일 벡터 코사인 검색에 모델 이름만 바꿔 넣을 수 없다. 이번에는 검색 구조 고정이라는 조건 때문에 보류하며 성능 열세로 제외한 것이 아니다. https://huggingface.co/nlpai-lab/KURE-v2
- **multilingual-e5-large-instruct:** 유효한 다국어 후보지만 첫 비교를 세 개로 제한하므로 예비 후보. 512토큰 제한과 query instruction 준수 여부를 확인해야 한다. Qwen 호출 경로가 부적합하면 재검토한다. https://huggingface.co/intfloat/multilingual-e5-large-instruct
- 더 큰 모델이나 다른 상용 API는 열세로 판정하지 않았다. 이번에는 현재 모델과 비슷한 규모의 공개 모델로 범위를 좁혔다. 후보들이 제품 기준에 미달하면 범위를 다시 연다.

## 조회 재현 및 결과

아래는 모델 추론이 아닌 공개 메타데이터 조회다. 키·원문 자막을 보내지 않았다.

```sh
hf models info nlpai-lab/KURE-v1 --expand inferenceProviderMapping --format json
hf models info BAAI/bge-m3 --expand inferenceProviderMapping --format json
hf models info Qwen/Qwen3-Embedding-0.6B --expand inferenceProviderMapping --format json
hf models info nlpai-lab/KURE-v2 --expand inferenceProviderMapping --format json
hf models card Qwen/Qwen3-Embedding-0.6B --text
```

| model | provider | status | task |
|---|---|---|---|
| KURE-v1 | hf-inference | live | feature-extraction |
| bge-m3 | hf-inference | live | sentence-similarity |
| Qwen3-Embedding-0.6B | deepinfra | live | feature-extraction |
| Qwen3-Embedding-0.6B | hf-inference | error | feature-extraction |
| KURE-v2 | hf-inference | live | sentence-similarity |

live는 메타데이터 상태이며 계정의 실제 사용 권한·호출 성공·지연·비용 보장이 아니다.

## 비교 설계와 통과 기준 제안 — 아직 확정 아님

1. 기존 확정 10문항과 기준선의 89문단 스냅샷을 개발 비교에 사용한다. 운영 DB를 덮어쓰지 않고 후보별 벡터를 별도로 저장한다. 이미 본 질문이므로 독립 최종 평가라고 쓰지 않는다.
2. 동일 본문·경계·시간·전체 검색 범위·top_k=3·코사인 검색·임계치 없음으로 고정한다. 질문과 문단 모두 해당 후보로 임베딩한다. BGE는 dense만 사용한다.
3. 모델별 공식 권장 입력 형식은 지킨다. Qwen query instruction은 비교 전에 고정하고 본문에는 붙이지 않는다. '공평함'을 이유로 필요한 입력 형식을 없애지 않는다. 정규화·pooling·정밀도·토큰 절단·모델 revision·제공자를 기록한다.
4. 시간 겹침 적중은 보조 지표. 주 품질 지표는 상위 3개 안에 실제 답의 근거가 충분한 문단이 있는지로 두고 완전/부분/무관을 구분한다. AI 초안 검토 뒤 사용자 최종 검수. 한국어 본문과 영어 본문 결과를 별도로 적는다.
5. **교체 기준 제안:** 현재 사람이 적합하다고 판정한 질문을 놓치지 않고, 부분/실패 사례를 개선해야 품질 개선으로 판단한다. 차이가 없으면 기존 모델 유지가 기본. 속도·비용 개선으로 바꾸려면 그 목표를 실행 전에 별도로 정한다. 기존 AI 7/8을 사용자 승인 기준으로 자동 고정하지 않는다.
6. 답 없는 2문항은 반환된 결과의 성격을 기록한다. 강제 top-3 검색에서 거절 0/2를 모델 선택의 단독 탈락 기준으로 쓰지 않는다. 점수 절대값을 모델 간 비교하지 않는다.
7. **응답 시간·비용의 수치 상한은 미확정.** 제공 경로와 예상 비용 확인 후 실행 전에 사용자에게 짧은 제안으로 확정한다. 임베딩 API 시간과 전체 검색 시간을 분리한다. 제공자가 다르면 '모델 자체 속도'가 아니라 해당 배포 경로의 속도다. 첫 요청·반복 요청·오류·재시도를 모두 기록한다.
8. 모델을 고른 뒤 새 질문으로 확인한다. 현재 10문항은 자동 시간 겹침 8/8로 차이가 드러나지 않을 수 있다. 동률을 우승으로 포장하지 않는다. 정답이 어떤 단일 문단에도 완결되게 존재하지 않는 사례는 청킹 문제로 구분한다.

종료: 품질·운영 조건을 충족하고 새 사례에서도 확인되면 채택 또는 유지. 세 후보가 모두 부적합하면 실패 원인을 먼저 검토하고 후보를 무한히 늘리지 않는다.

## 지금 이력서에 쓸 수 있는 범위

조사만으로 '세 모델을 비교해 선정'이라고 쓰지 않는다. 기존 KURE-v1 의미 검색 구현·10문항 기준선 평가 서술은 유지한다. 실제 비교와 최종 확인이 끝난 뒤 후보 선정 조건·표본·결과·채택 이유로 보강한다.

## 개발 비교 실행 — 2026-09-12

실행 전에 합의한 기준은 **기존 답 있는 질문의 hit@3를 잃지 않으면서 정답 문단 순위가 개선되는가**였다. 차이가 명확하지 않을 때만 세 번째 후보를 추가하기로 했다.

- 고정: 사용자 검수 10문항 중 답 있는 8문항, 같은 89문단·경계·본문, 전체 검색, top-3, 임계치 없음, 정규화한 1024차원 벡터의 코사인 유사도.
- 두 모델 모두 이번 실행에서 질문과 문단 벡터를 새로 만들었다. 운영 DB와 배포 모델은 변경하지 않았다.
- 자동 정답은 영상 ID와 검수된 시간 구간의 겹침이다. 제목이나 현재 문단 번호를 정답으로 사용하지 않았다.

| 모델 | hit@3 | 정답 1위 | MRR | 문단 임베딩 6배치 | 질문 임베딩 1배치 |
|---|---:|---:|---:|---:|---:|
| KURE-v1 | 8/8 | 4/8 | 0.729 | 24.613초 | 0.524초 |
