## 1. 무엇을 왜 했나

출발점은 이거였다. `blueprint-status.md` 6장은 **임베딩 비교**를 1순위로 적어 두었는데,
막상 하려니 비교에 쓸 정답지가 10문항뿐이었다. 그 10문항도 **dev/test 구분이 없어서**
같은 문항으로 커트라인을 고르고 같은 문항으로 검증하는 모양이었다. 그래서 순서를 이렇게 잡았다.

```
정답지 30문항(dev 15 / test 15)  →  임베딩 모델 선정  →  커트라인 확정
```

그런데 정답지를 만들려고 보니 **라이브러리에 영상이 2편밖에 없었다.**
기존 10문항이 가리키던 8편 중 6편이 사라진 상태였다(누가 언제 지웠는지는 모른다).
그래서 복구 → DB 정리 → 정답지 생성 순으로 내려왔다.

## 2. 코드 변경 4건

### 2-1. 목차 폴백 제거 — 이력서 불일치 해소

`blueprint-status.md` 부록 B의 2번 항목이다.

> 이력서: "확인되지 않으면 저장하지 않도록 구현"
> v2 실물: 재시도 후에도 실패하면 **첫 문장으로 폴백해 저장** (`outline.ts:77`)

`label()` 이 실패하면 이제 `null` 을 돌려주고 **저장하지 않는다.** 부르는 쪽 세 곳을 같이 고쳤다.

| 파일 | 변경 |
| --- | --- |
| `src/lib/outline.ts` | `fallbackTitle()` 삭제, 반환형 `Labeled \| null` |
| `src/app/api/outline/route.ts` | null 을 걸러 저장, 버린 수를 `dropped` 로 응답(`fallback` 필드 제거) |
| `scripts/rebuild-video.ts` | 같은 처리, 로그에 버린 수 표시 |
| `tests/outline.test.ts` | 폴백 기대 테스트 3건을 "버린다" 기대로 교체 |

복구 실행에서 실제로 1건이 버려졌다(`PlawByYfV8k`, 목차 5개 · 버림 1).

### 2-2. 라이트 모드가 없던 버그

`globals.css` 가 다크 값을 `@media (prefers-color-scheme: dark) { @theme { ... } }` 안에 두고 있었다.
**Tailwind v4 는 `@theme` 을 미디어쿼리 밖으로 끌어올린다.** 조건이 사라져 다크 값이 항상 이겼다.
컴파일된 CSS 에 `--color-bg` 가 하나뿐이었고 값이 `#0c0c0e` 였다 — 라이트 OS 사용자도 전부 다크로 봤다.

다크 값을 `@theme` 이 아니라 평범한 `:root` 로 덮게 고쳤다. 지금은 `#fff` 기본 / 미디어쿼리 안에 `#0c0c0e` 로 분리된다.

**주의: 이 수정으로 라이트 모드 화면이 처음 드러났다.** 의도가 다크 고정이었다면 되돌려야 하는데,
그때는 `@theme` 의 라이트 값 자체를 다크 값으로 바꾸는 게 맞는 방법이다.

### 2-3. `listVideos` 길이 추정 필터 제거

필터가 "최장 문단 340자 초과 = 모델 청킹" 으로 문단 출처를 추정하고 있었다.
`NtHSSWC04Do`(최장 227자)가 여기 걸려 목록에서 빠졌다 — 모델이 나눈 4문단짜리 짧은 영상이다.
**길이로 출처를 맞히는 건 성립하지 않는다.** 필터를 지웠고, 남은 조건은 "목차가 있는가" 하나다.

문단 출처 컬럼이 생기면 추정 없이 가를 수 있다. 그건 스키마 변경이라 손대지 않았다.

### 2-4. 읽기 화면에 목차 제목 삽입

목차가 가리키는 문단 위에 그 제목을 넣었다(`Reader.tsx`). 옆 목차만 있으면 눌러서 뛴 뒤
"여기가 몇 번이었지"를 다시 옆에서 찾아야 하고, 그냥 읽어 내려갈 때는 화제 전환이 보이지 않았다.
`outline.seq` 가 청크 `seq` 와 같은 값이라 대응표 한 줄로 끝났다. 새 데이터는 없다.

## 4. 정답지 v2 초안

`scripts/make-goldenset.ts` 로 만들었다. 산출물 두 개다.

- `web/data/evals/search/questions.draft.v2.json`
- `web/data/evals/search/questions.draft.v2.review.md` — 질문 + 정답 문단 원문 + 판정칸

### 설계 (실행 전에 정했다)

| 항목 | 값 | 이유 |
| --- | --- | --- |
| 문항 | 30 | 10문항으로는 dev/test 를 못 나눈다 |
| 답 있음 : 답 없음 | 22 : 8 | 기존 2개로는 거절률이 0·50·100% 셋 중 하나로만 나온다 |
| dev : test | 15 : 15 | dev 로 커트라인을 고르고 test 로 **한 번만** 확인 |
| 코퍼스 | 8편 · 89문단 | 검색이 실제로 뒤지는 범위와 일치 |

### 만드는 방식

질문은 `claude-sonnet-5` 가 썼고, **인용문이 해당 문단에 글자 그대로 있는지 코드가 대조했다**
(`verify.ts` 의 `holds`). 통과한 것만 남긴다 — 목차 검증과 같은 장치다.

단, 이 초안은 모델에 현재 문단 경계를 보여주고 생성해 **현재 청킹에 유리할 수 있다.**
확정본을 다시 만들 때는 문단 표시 없이 이어진 전사문을 입력하고, 생성된 인용문으로
정답 시각을 찾도록 `make-goldenset.ts`를 수정했다. 현재 30문항은 검수용 초안이며,
이 변경 뒤 다시 생성한 결과가 아니다.

- 답 있음: 영상마다 따로 생성. 한 편에서 몰아 뽑으면 질문끼리 겹친다.
- 답 없음: **문단을 보여주지 않고 제목·목차만** 주고 생성. 문단을 보여주면 그 안에서 답을 찾아버린다.

### 결과

**최종 채택된 답 있음 문항의 인용 대조 22/22 통과** (지어낸 인용 0건). 영상별로 3문항씩, `NtHSSWC04Do` 만 1문항
(문단이 4개뿐이라 3개를 뽑으면 서로 겹친다).

`review_status` 는 전부 `draft` 다. **사람 검수 전이다.**

질문은 전부 한국어다. 현재 측정 범위는 **한국어 질문으로 한국어·영어 전사문을 찾는 검색**이다.
영어 질문 품질까지 주장하려면 영어 문항을 별도로 추가해야 한다.

## 5. 확인받고 싶은 것 — 판단이 갈릴 수 있는 자리

### 5-1. `pZjYP24kTjc` — 사용자 판정(2026-09-13): **평가에서만 빼는 게 맞았다**

비교 조건을 통일하려고 뺀 것 자체는 타당하다. 다만 **서비스 DB 에서 지울 일은 아니었다** —
평가 대상에서만 제외하면 될 일이었다.

**복구 대상으로 기록한다.** 청킹 방식이 최종 확정되면 같은 방식으로 다시 만들어 라이브러리에 되돌린다.
그때까지는 골든셋 코퍼스에 넣지 않는다.

| 항목 | 값 |
|---|---|
| 영상 | `pZjYP24kTjc` · 타인의 평가 [털게라이브 7일차 마지막날] |
| 지운 상태 | 문단 19 · 목차 19 (코드 청킹, 목차는 Sonnet) |
| 복구 방법 | `node --experimental-websocket --env-file=.env.local --import tsx scripts/rebuild-video.ts pZjYP24kTjc` |
| 조건 | 청킹 방식 확정 후. 비용 약 $0.1 |

### 5-2. 재전사를 한 게 맞나

4편은 저장된 전사문이 있어서 전사를 건너뛸 수 있었다. 전사 모델 통일을 택해 다시 돌렸다.
`8cp0YvSpDA8` 의 저장본만 `gemini-3.5-flash` 였고 나머지는 `3.8-flash` 였다.

### 5-3. 답 없음 8문항 중 두 개가 위험하다

- `N03` "코난 오브라이언이 나중에 왜 토크쇼에서 하차하게 됐나요?"
- `N06` "이미 관계가 틀어진 사람과 화해하려면 어떻게 해야 하나요?"

둘 다 코퍼스에 **주제가 가까운 영상이 있다.** 점수가 높게 나와 거절에 실패할 수 있다.

**사용자 판정(2026-09-13): 둘 다 남긴다.** 주제가 비슷해도 답이 없는 질문이 커트라인의
진짜 성능을 보여준다. 쉬운 문항만 남기면 거절률이 좋아 보이는 착시가 생긴다.
특히 `N03` 이 그런 사례다. `N06` 은 "화해 방법"이 실제로 코퍼스에 없는지만 검수에서 확인한다.

### 5-4. 검색 커트라인은 아직 없다 — **뒤로 미루는 게 맞다(사용자 확인)**

`lib/search.ts` 에 임계치 코드가 없다. 점수가 낮아도 그대로 돌려준다.
기존 측정에서 답 있음 1위 0.545~0.667, 답 없음 0.544·0.619 로 **분포가 겹쳐**
단일 임계치로 10문항 중 8을 못 넘겼다. 그래서 숫자를 찍지 않고 순서를 뒤로 미뤘다 —
커트라인은 임베딩 모델에 딸린 값이라 모델을 바꾸면 다시 정해야 한다.

### 5-5. 랜딩·읽기 화면을 꽤 고쳤다

`app/page.tsx` 를 오늘 여러 번 손봤다(섹션 순서, 활자 크기, FAQ 아코디언, 제품 화면 캡처 추가).
Codex 가 쓴 구조 위에 덧댄 것이라 의도와 어긋난 곳이 있을 수 있다.
캡처는 `scripts/shoot-reader.mjs` 로 실제 화면을 찍는다(`public/shots/reader-light.png`).
UI 를 고치면 다시 돌려야 한다.
