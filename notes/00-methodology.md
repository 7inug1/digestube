# 기술 선정 프레임워크

## 발표에서 못 답한 질문

1. 검색 임계치 0.86, 어디서 나온 숫자예요?
2. SQLite가 5배 빠르다는데 뭐랑 비교한 거예요?
3. 자막 오류율 10.10% → 6.88%, 뭘 보고 잰 거예요?
4. 지어낸 글자 375자 → 0자, 어떻게 셌어요?
5. 답변 모델로 Claude Haiku를 왜 골랐어요?

다섯 개 다 **"그 숫자 어디서 나왔냐"**를 묻고 있다. 자료에는 결론만 있었다.

## 왜 못 답했나

- **안 재고 정했다** — 답변 모델은 다른 것과 비교한 적이 없다.
- **재고 나서 코드를 안 남겼다** — "수천 개 규모"라고 했는데 실제로는 189개였고, 다시 돌려볼 수 없어 확인이 안 된다.
- **출처가 다른 숫자를 나란히 놨다** — 우리가 잰 6.88% 옆에 남의 벤치마크 11.34%를 놨다.

## 여섯 단계

마음속으로 이미 "이거 쓰고 싶다"가 정해진 채 비교를 시작하면, 일부러 그러지 않아도 그쪽이 이긴다. 그걸 막는 순서다.

**1. 후보를 공평하게 모은다**
후보가 갈리는 축을 먼저 정하고 축마다 빈 칸 없이 채운다. 검색 결과만 쓰면 덜 알려진 쪽이 통째로 빠진다. 음성인식에서는 만든 곳(국내 / 해외 / 연구기관 / 개인)과 돌아가는 곳(내 컴퓨터 / 남의 서버)으로 나눠 20개를 모았다.

**2. 뺄 때는 누가 봐도 확실한 이유로만 뺀다**
재보지 않아도 예/아니오가 갈리는 조건으로만 뺀다. "성능이 별로일 것 같다"는 재봐야 아는 거라 안 된다. 음성인식에서는 한국어 미지원·상업적 이용 불가·서비스 종료로 20개 중 3개를 뺐다.

**3. 남은 후보를 무엇으로 비교할지 정한다**
남은 후보끼리는 조건을 다 채웠으니 예/아니오로 안 갈린다. 잣대를 만들되 재기 전에 확정한다. 재고 나서 정하면 원하는 쪽이 이기게 고를 수 있다.

표준 지표라도 그냥 안 쓰고, 그 기술이 우리 서비스에서 하는 일과 맞는지 본다. CER은 "콘텐츠→컨텐츠"(검색은 그대로 걸린다)와 "체류시간→치료시간"(그 문단이 검색에서 사라진다)을 똑같이 1점으로 센다. 그래서 뜻이 바뀐 것만 세는 잣대를 따로 만들고 CER은 참고로 남겼다.

**4. 사람이 직접 정답지를 만든다**
채점하려면 정답이 있어야 하는데, 그대로 갖다 쓸 만한 정답은 없다. 채널이 직접 올린 자막에도 틀린 데가 있다. 그래서 사람이 영상을 보면서 자막을 한 줄씩 맞춰보고, 틀린 곳을 고친 다음에야 정답지가 된다. 음성인식에서는 채널 13곳을 뒤져 쓸 만한 2곳을 골라 이 작업을 했다.

건너뛰면 정답지 잘못이 후보 잘못으로 찍힌다. 검수 없이 잰 한 영상은 4.14%였는데, 정답지 결함을 걷어내니 0.56%였다. **틀린 것의 86%가 정답지 잘못이었다.**

**5. 남은 후보를 직접 잰다**
남의 벤치마크는 참고까지만 쓴다. 쓴 자료가 다르면 순위가 옮겨오지 않는다. Whisper는 그쪽에서 11.39%였는데 우리 영상으로는 2.86%였다.

후보마다 조건을 똑같이 맞춘다. 헛소리 필터를 한쪽에만 걸었을 때 8.73%였던 값이 양쪽에 걸자 3.04%가 됐다.

결과가 매번 달라지는 기술은 여러 번 잰다. 같은 오디오 3회에 2.25~3.62%로 흔들렸다.

**6. 무엇을 보고 골랐는지 남긴다**
뭐랑 비교했는지, 무슨 잣대로 쟀는지, 돌린 코드, 아직 확인 못 한 부분을 같이 남긴다. 결론만 적으면 나중에 되짚을 수 없다. 발표에서 답을 못 한 게 이것 때문이다.

잣대가 여러 개면 다 같이 놓고 본다. CER은 클라우드가 나은데(2.36% / 로컬 2.86%) 뜻이 바뀐 오류는 반대였다(8곳 / 로컬 6곳). **CER만 봤으면 잘못된 쪽을 골랐다.**

잣대끼리 결론이 갈릴 때만 점수를 매겨 합산한다. 가중치는 잣대를 둘씩 짝지어 정한다. 순서대로 하나씩 적용해 걸러내지는 않는다. 먼저 적용한 잣대가 결과를 정해버린다.

## 고를 때와 써본 뒤를 구분한다

오픈소스라 버그를 직접 고칠 수 있었던 건 도움이 됐지만, 겪어보기 전엔 알 수 없는 일이다. 선정 이유로 쓰지 않고 "나중에 알게 된 것"으로 따로 적는다.
