# 목차 생성 — 배관

상태: 붙임. **모델은 임시 고정** (청사진 4번 자리는 아직 `재봄`)

## 무엇을 붙였나

```
문단 → 제목 만들기(lib/outline.py) → 근거 대조(lib/verify.py) → 저장
                                          ↓
                                  원문에 없는 인용은 버림
```

인용 통과율이 여기서 나온다. 4번 자리에서 후보를 가르는 지표다.

## 정한 것과 그 이유

**모델을 지금 고르지 않는다.** 청사진 4번 자리는 후보 15개 중 6개만 돌렸고
표본이 영상 3편·회당 2번이다. Groq 쪽 셋은 무료 한도에 걸려 4회씩만 돌았다.
지금 고르면 어차피 다시 골라야 하므로 `lib/outline.py` 의 `MODEL` 상수 하나로
두고 Claude Haiku 4.5 를 임시로 박았다. 임베딩에서 쓴 방식과 같다.

**프롬프트를 다듬지 않는다.** 프롬프트를 모델에 맞춰 손보면 나중에 후보를
나란히 놓고 잴 수 없다. 조건을 똑같이 맞춘다는 규칙(방법론 5단계)이 여기에도
걸린다 — 헛소리 필터를 한쪽에만 걸었다가 8.73%가 3.04%로 바뀐 일과 같은 종류다.

**근거 대조를 어떻게 판정하나** ← 이게 통과율 숫자를 바꾼다

글자 그대로 일치를 요구하면 공백이나 구두점 하나 차이로 멀쩡한 인용이
떨어진다. 모델이 "그, 저기" 같은 군더더기를 빼고 옮기기도 한다. 그래서
**공백과 구두점을 지운 뒤 부분 문자열**로 본다.

이 완화가 어디까지 봐주는지에 따라 통과율이 달라진다. 후보를 비교할 때는
양쪽에 같은 판정을 걸어야 한다. 판정 규칙은 `lib/verify.py` 한 곳에만 있다.

**목차는 덤이다.** 실패해도 문단과 검색은 그대로 남는다. 임베딩 실패 처리와
같은 자리에 같은 모양으로 넣었다.

## 지금 측정값

영상 1편(문단 3개) 기준.

| | 값 |
|---|---|
| 인용 통과율 | 100% (3/3) |
| 걸린 시간 | 3.7초 (문단 3개) |
| 모델 | claude-haiku-4-5-20251001 |

**이 숫자로는 아무것도 못 고른다.** 영상 1편이다. 청사진 테스트 1에서 Haiku 가
83% 였던 것과도 다른데, 문단 수와 내용이 달라 비교가 안 된다.

## 다시 돌리는 법

```
python3 scripts/outline.py <영상번호>
python3 scripts/outline.py --all
```

전사를 다시 받지 않고 저장된 문단만 쓴다. **모델을 바꿔 재려면 `MODEL` 을 고치고
이걸 돌린다** — 같은 문단에 같은 프롬프트를 거는 경로가 여기 하나뿐이라
후보 비교는 반드시 이쪽으로 한다.

## 아직 안 한 것

- 후보 비교. 코퍼스가 1편이라 못 한다
- 4번 자리의 남은 결정 — 인용 통과율과 속도가 반대로 간다. 어디까지 기다릴지는
  영상이 여러 편이어야 판단된다
- 새로 넣기(`POST /api/ingest`) 경로에서의 목차 생성은 코드만 넣었고 아직
  실제로 태워보지 못했다. 크레딧이 필요하다
