# 목차 모델 사람 평가 — 작은 비교부터

2026-09-09 사용자와 합의한 기준:

1. 문단의 핵심을 대표하는가?
2. 원문에 없는 주장을 덧붙이지 않는가?
3. 목차만으로도 어떤 내용인지 파악 가능한가?

세 기준을 각각 0(미충족), 1(부분 충족), 2(충족)로 평가한다.
세부 기준은 생성 전 `scripts/pilot-outline.mjs`에 정의했다.
사람 평가가 끝나기 전에는 우승 모델이나 품질 통과율을 선언하지 않는다.

후보: 현재 사용 모델 Sonnet 5, 작은 모델 Haiku 4.5, 다른 계열 gpt-oss-120b(Groq).
전체 모델을 소거해서 남긴 후보가 아니라 기존 연동을 활용한 제한된 첫 비교다.

## 실행

`web/`에서 Node 22 이상:

```sh
node --env-file=.env.local scripts/pilot-outline.mjs
```

Node 20에서는 `--experimental-websocket`도 추가한다.

현재 DB의 각 영상에서 순서상 가운데 문단을 하나씩 선택한다. 출력 품질을 보기 전에 입력을
manifest.json에 고정한다. 후보당 1회 실행하며 기존 bench-outline.mjs의 프롬프트를 유지한다.
Sonnet은 temperature를 생략하고 나머지는 0을 사용한다. 출력 토큰 한도는 기존 연동과
같이 Anthropic 300, Groq 800이다. 따라서 입력·프롬프트는 같지만 모든 생성 설정이
동일한 실험은 아니다. 공급업체·모델·설정을 포함한 현재 호출 구성의 비교다.

결과 디렉터리: `web/data/evals/pilot-<실행시각>/`

- manifest.json: 입력 스냅샷, 프롬프트, 후보 및 설정
- results.json: 응답 원문, 사용 토큰, 시간, 자동 검사 (요청마다 저장)
- blind-review.md: 사람 채점표. 문단마다 후보 표시 순서를 순환 변경
- answer-key.json: 채점 후 확인할 후보 대응표

제목만 보고 내용 파악 점수를 적은 뒤, 원문을 읽고 나머지를 채점한다.
같은 제목이면 동점을 허용한다. 원문이 불명확하면 판단 보류와 이유를 적는다.
자동 인용 대조는 공백·구두점을 무시한 부분 일치이며 제목의 사실성을 검증하지 않는다.
실패한 호출을 제목 품질 0점으로 섞지 않고 별도로 집계한다.

## 한계와 다음 단계

이것은 채점 기준을 실제 예시에 적용하는 연습이다. 한 번씩만 생성하므로 반복 안정성을
평가하지 않는다. 전사 mode가 기록되지 않은 기존 코퍼스여서 native 전용 평가도 아니다.
문단별 제목만 비교하므로 전체 목차의 흐름과 중복성은 아직 평가하지 않는다.

사람 채점 후 기준을 다듬는 경우 이번 입력은 연습용으로 남긴다. 이후 별도의 입력을 고정하고,
영상 전체 목차와 반복 실행, 비용·지연을 함께 비교한 뒤 최종 모델을 결정한다.
실제 비용은 usage만으로 단정하지 않고 실행 시 제공업체 요금과 대조해야 한다.
