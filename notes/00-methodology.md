# 기술 선정 프레임워크

## 발표에서 못 답한 질문

1. 검색 임계치 0.86, 어디서 나온 숫자예요?
2. SQLite가 5배 빠르다는데 뭐랑 비교한 거예요?
3. 자막 오류율 10.10% → 6.88%, 뭘 보고 잰 거예요?
4. 지어낸 글자 375자 → 0자, 어떻게 셌어요?
5. 답변 모델로 Claude Haiku를 왜 골랐어요?

다섯 개 다 **"그 숫자 어디서 나왔냐"**를 묻고 있다. 자료에는 결론만 있었다.

## 왜 못 답했나

- **안 재고 정했다** — 답변 모델은 다른 것과 비교한 적이 없다.
- **재고 나서 코드를 안 남겼다** — "수천 개 규모"라고 했는데 실제로는 189개였고, 다시 돌려볼 수 없어 확인이 안 된다.
- **출처가 다른 숫자를 나란히 놨다** — 우리가 잰 6.88% 옆에 남의 벤치마크 11.34%를 놨다.

## 여섯 단계

마음속으로 이미 "이거 쓰고 싶다"가 정해진 채 비교를 시작하면, 일부러 그러지 않아도 그쪽이 이긴다. 그걸 막는 순서다.

**근거의 자격** — 우리 영상으로 재고 다시 돌려볼 수 있어야 근거다. 남의 벤치마크는 참고까지만. 실제로 Whisper는 그쪽 벤치마크에서 11.39%였는데 우리 영상으로 재니 2.86%였다.

**1. 후보를 공평하게 모은다**
칸을 먼저 만들고 채운다(국내 기업 / 해외 / 연구기관 / 오픈소스). 검색 결과만 쓰면 덜 알려진 쪽이 통째로 빠진다. → 20개.

**2. 뺄 때는 누가 봐도 확실한 이유로만 뺀다**
한국어 미지원, 상업적 이용 불가, 서비스 종료. "성능이 별로일 것 같다"는 안 된다. → 20개 중 3개만 제외.

**3. 채점 기준을 재기 전에 정한다**
표준 지표라도 그냥 안 쓴다. CER은 틀린 글자를 전체 글자로 나눈 값인데, 아래 둘을 똑같이 1점으로 센다.

- "콘텐츠" → `컨텐츠` : 검색은 그대로 걸린다
- "체류시간" → `치료시간` : 그 문단이 검색에서 아예 안 나온다

→ 뜻이 바뀐 것만 따로 세는 기준을 추가하고, CER은 참고로만 남겼다.

**4. 정답이 진짜 정답인지 확인한다**
채널 13곳을 뒤져 2곳을 골랐고, 사람이 영상과 대조했다. 한 영상은 앞 30초에 자막이 없었다. 모르고 잰 값 4.14%, 그 구간을 빼면 0.94%. **"오류"의 77%가 정답지 결함이었다.**

**5. 같은 조건에서 여러 번 잰다**
헛소리 필터를 한쪽에만 걸었을 때 8.73%, 양쪽에 걸자 3.04%. 같은 오디오 3회에 2.25~3.62%로 흔들렸다.

**6. 어디까지 확인했는지도 같이 적는다**
CER은 로컬 2.86% / 클라우드 2.36%. 뜻이 바뀐 오류는 로컬 6곳 / 클라우드 8곳으로 반대. **CER만 봤으면 잘못된 쪽을 골랐다.** 사람이 아직 안 본 숫자는 안 봤다고 적는다.

직접 재서 우열이 안 갈릴 때만 점수를 합산한다. 가중치는 기준을 둘씩 짝지어 정한다. 기준을 하나씩 순서대로 적용해 걸러내지는 않는다. 먼저 적용한 기준이 결과를 정해버린다.

## 고를 때와 써본 뒤를 구분한다

오픈소스라 버그를 직접 고칠 수 있었던 건 도움이 됐지만, 겪어보기 전엔 알 수 없는 일이다. 선정 이유로 쓰지 않고 "나중에 알게 된 것"으로 따로 적는다.
